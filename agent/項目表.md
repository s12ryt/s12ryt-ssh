# 專案文件與依賴

## 入口與介面

- `main.go`：Windows GUI 應用程式入口、vault 啟動流程與 Gio 視窗。
- `internal/gui/`：Gio 視圖、設定精靈、登入與資源操作畫面；只呼叫 backend/service。

## 核心 backend

- `internal/config/`：非敏感 vault metadata 與 profile 型別；不再負責明文 secret persistence。
- `internal/vault/`：UUID、KDF、AES-GCM、復原金鑰與 vault 序列化。
- `internal/securestore/`：Windows bootstrap secret 安全儲存 adapter。
- `internal/storage/`：S3/R2 物件儲存與記憶體測試 backend；vault R2 adapter 依賴此介面。
- `internal/database/`：MySQL/PostgreSQL client 與 SQL vault adapter；避免循環依賴。
- `internal/ssh/`：SSH host key 驗證、timeout、Exec 與 PTY session。

## 測試與文件

- 各 package 的 `*_test.go`：先 RED、後 GREEN、再 REFACTOR；優先測可觀察契約。
- `.github/workflows/ci.yml`：push/PR 的 Windows CI、版本矩陣、測試、靜態檢查、build、安全掃描。
- `.github/workflows/release.yml`：語意化版本 tag/手動觸發的 Windows amd64/arm64 發行建置與 checksums。
- `README.md`：GUI 建置、首次設定、vault 與功能說明。
- `agent/question.md`：唯一需求與驗收依據。
- `agent/deep_todos.md`：歷史、基線與當前進度。
- `agent/memory.md`：本次檔案操作與驗證紀錄。

## 主要依賴方向

`main.go -> internal/gui -> internal/vault + internal/securestore + internal/ssh/storage/database`

`internal/vault -> storage.Storage 或 vault backend interface`

`internal/database -> config`；`internal/storage -> config`；`internal/ssh -> config`

backend package 不依賴 Gio，確保可單元測試與重用。
